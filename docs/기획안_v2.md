# 웨딩 사진 액자 편집 서비스 개발 기획안 v2

> v1 대비 변경 요약: 확정 결정 사항 반영(액자 미리보기 전용, 방향 기반 레이아웃 자동 변형, Custom 규격 상한, mm 좌표계 확정, 완전 클라이언트 사이드, 슬롯 고정+내부 크롭 방식), 원본/편집용 이미지 이중 관리, Undo/Redo, IndexedDB 자동 저장, Safe Area, MVP 릴리스 범위 정의 추가.

---

## 1. 프로젝트 개요

사용자가 결혼식 사진을 업로드하여 액자 출력용 인쇄 파일을 직접 만들 수 있는 웹 서비스.

핵심 가치는 **WYSIWYG 인쇄 정확성**이다. 화면에서 보는 비율·배치·여백이 300dpi PDF 출력물과 1:1로 일치해야 하며, 사용자는 디자인 지식 없이 3분 이내에 인쇄소 전달 가능한 파일을 완성할 수 있어야 한다.

### 아키텍처 원칙 (확정)

**완전 클라이언트 사이드.** 사진은 서버로 전송하지 않는다. 업로드 → 편집 → PDF 생성 전 과정이 브라우저 안에서 완결된다.

- 근거 ①: 웨딩 사진의 민감성. "사진은 내 기기를 벗어나지 않습니다"를 랜딩 및 에디터 상단에 명시적으로 노출하여 신뢰 요소로 활용한다.
- 근거 ②: 스토리지/트래픽 비용 제로.
- 근거 ③: 개인정보처리방침 부담 최소화.
- 트레이드오프: 기기 간 작업 이어하기 불가. MVP에서는 IndexedDB 자동 저장(동일 기기 복구)까지만 지원하고 크로스 디바이스는 이후 과제로 둔다.

## 3. 좌표계 및 단위 정책 (확정 · 최우선 규칙)

**모든 상태는 mm 단위로 저장한다. mm가 진실의 원천(Single Source of Truth)이다.**

화면 px로 저장하면 창 크기 변경·기기 이동 시 좌표가 틀어지고 추출 시 환산 오차가 누적된다. mm 기준을 유지하면 화면과 출력이 항상 동일 비율을 보증한다.

```typescript
// utils/convertMM.ts
export const MM_PER_INCH = 25.4;
export const EXPORT_DPI = 300;

/** 추출용: mm → 300dpi px */
export const mmToExportPx = (mm: number) => (mm / MM_PER_INCH) * EXPORT_DPI;

/** 화면용: mm → 화면 px (컨테이너 크기에 맞춰 동적 계산되는 screenScale 사용) */
export const mmToScreenPx = (mm: number, screenScale: number) => mm * screenScale;
```

- 내부 좌표계: mm (모든 스토어 상태)
- 화면 표시: `mm × screenScale` — screenScale은 캔버스 컨테이너 크기에서 매 리사이즈마다 계산
- 추출: `mm / 25.4 × 300`

| 사이즈 | mm | 비고 |
| --- | --- | --- |
| A4 | 210 × 297 | |

| A3 | 297 × 420 | |
| 4×6 | 102 × 152 | |

| 8×10 | 203 × 254 | |
| Custom | 사용자 지정 | 최소 50×50mm ~ 최대 420×594mm(A2), mm 정수만 허용 |

### Custom 상한 근거 (확정)

A2 300dpi = 4961×7016px로 데스크탑 크롬 기준 캔버스 안전 한계 이내. A2 초과는 추출이 불안정하므로 차단하고 "A2 초과 규격은 지원하지 않습니다" 안내를 표시한다.

### 용지 방향 (확정)

용지 선택 직후 **세로/가로 토글**을 제공한다. 기본값은 세로(웨딩 액자의 절대 다수). 방향 변경 시 캔버스 비율이 즉시 실제 비율로 전환된다.

## 5. 인쇄 영역 정책

### Bleed (재단 여유)

- 3mm / 5mm 선택, **기본값 3mm**
- Bleed 영역은 회색 반투명으로 표시

### Safe Area (안전 여백) — v2 신규

- 재단선 안쪽 **5mm 고정** (옵션으로 제공하지 않음 — 선택지를 줄여 3분 완성 목표 유지)
- 얼굴 등 핵심 콘텐츠가 재단선에 걸리는 사고 방지

### 화면 표기 규칙

```text
┌────────────────────────────┐
│  Bleed (회색 반투명)        │  ← 재단 시 잘려나가는 영역

│  │ 재단선 (실선)         │  │  ← 실제 완성 크기
│  │  ┌────────────────┐  │  │
│  │  │ 안전선 (점선)   │  │  │  ← 이 안에 얼굴·중요 요소 배치
│  │  │                │  │  │
│  │  └────────────────┘  │  │
│  └──────────────────────┘  │
└────────────────────────────┘
```

## 6. 사진 레이아웃

### 제공 레이아웃

- 고정: 1 / 2 / 3 / 4 / 6 / 9장
- 자유 배치 (2차 릴리스)
- 사용자 지정 레이아웃 편집기 (3차 릴리스)

### 방향 기반 자동 변형 (확정)

레이아웃 변형을 별도 선택지로 나열하지 않는다. **용지 방향에 따라 자동 결정**한다. 선택 단계를 늘리면 3분 완성 목표를 해치기 때문이며, 원하는 변형이 안 나오면 용지 방향을 바꾸면 되고, 그래도 부족한 케이스는 자유 배치로 커버한다.

| 레이아웃 | 세로 용지 | 가로 용지 |
| --- | --- | --- |
| 2장 | 상하 분할 | 좌우 분할 |
| 3장 | 상단 1장 크게 + 하단 2장 | 좌측 1장 크게 + 우측 2장 |
| 4장 | 2×2 | 2×2 |
| 6장 | 2열×3행 | 3열×2행 |
| 9장 | 3×3 | 3×3 |

```text
[2장 · 세로]        [2장 · 가로]        [3장 · 세로]
┌──────────┐      ┌─────┬─────┐      ┌──────────┐
│  PHOTO   │      │  P  │  P  │      │  PHOTO   │
├──────────┤      │     │     │      │ (크게)    │
│  PHOTO   │      └─────┴─────┘      ├─────┬────┤
└──────────┘                         │  P  │  P │
                                     └─────┴────┘
```

### 슬롯 간 간격 (gutter)

0 / 2mm / 5mm 세 단계, **기본 2mm**.

### 슬롯-사진 관계 (확정 · 핵심 설계)

**"슬롯 고정 + 내부 크롭" 방식.**

- 고정 레이아웃에서 슬롯은 움직이지 않는다.
- 사진은 슬롯에 clip된 상태로 슬롯 내부에서만 이동/확대된다 (인스타그램 크롭과 동일한 멘탈 모델).
- 사진을 슬롯에 드롭하면 `cover` 방식(빈 여백 없이 슬롯을 가득 채우는 최소 배율)으로 자동 채움 후 중앙 정렬.
- 자유 배치 모드에서만 사진 자체가 자유 이동/리사이즈되며 zIndex를 가진다.
- 두 모드는 상태 구조를 공유하고 `layoutMode: 'grid' | 'free'` 플래그로 렌더링 로직만 분기한다.

### 자유 배치 보조 기능 (2차)

스냅/정렬 가이드 필수: 중앙 정렬선, 사진 간 스냅, 균등 간격 가이드. 이것이 없으면 "디자인 지식 없이 3분 완성" 목표와 충돌한다.

## 7. 사진 업로드

### 방식

- Drag & Drop + 파일 선택 버튼 (React Dropzone)
- 다중 업로드 → 좌측(모바일: 하단) 사진 목록에 적재 → 슬롯으로 드래그 배치

### 지원 포맷

| 포맷 | 처리 |
| --- | --- |
| JPG / PNG / WEBP | 네이티브 |
| HEIC | heic2any로 클라이언트 변환. 변환 중(장당 1~2초) 썸네일 자리에 스피너 표시 |

### EXIF 회전 보정 (필수)

아이폰 사진의 EXIF Orientation을 읽어 로드 시점에 픽셀을 정방향으로 보정한다. 미처리 시 사진이 90도 회전되어 표시되는 치명적 결함이 된다.

### 원본/편집용 이중 관리 (필수)

웨딩 원본은 장당 10~20MB가 흔하다. 원본을 그대로 캔버스에 올리면 모바일에서 메모리 크래시가 발생한다.

```text
업로드 원본
  ├─ originalSrc: 추출(PDF) 시에만 참조         → IndexedDB Blob 보관
  └─ src: 장변 2000px 다운스케일 편집용 이미지    → 캔버스에 로드
```

- 편집·미리보기: `src` (다운스케일)
- 300dpi 추출: `originalSrc` (원본)로 교체 렌더링 후 추출

- Zustand + zundo 미들웨어로 히스토리 스택 관리

- 재방문 시 "이전 작업을 이어서 하시겠습니까?" 복구 프롬프트

## 10. 다운로드

### 포맷

- PNG / JPG (미리보기·공유용, 화면 해상도 기준)
- **300dpi PDF** (인쇄소 전달용, bleed 포함)

### 추출 파이프라인 (확정)

```text
편집용 이미지(src)를 원본(originalSrc)으로 교체
  ↓
Konva stage.toDataURL({ pixelRatio: exportScale })
  (exportScale = mmToExportPx(paperWidth) / screenCanvasWidth)
  ↓
jsPDF에 실측 사이즈(mm, bleed 포함)로 이미지 삽입
  ↓
다운로드
```

### 색공간 고지

브라우저 캔버스는 sRGB만 지원한다. 출력 파일은 **sRGB 기반 인쇄 파일**임을 다운로드 화면에 명시한다. CMYK 변환(서버사이드)은 장기 로드맵.

### 모바일 대용량 추출 제한

iOS Safari 등의 캔버스 크기/메모리 제한으로 A3 이상 300dpi 추출이 실패할 수 있다. **추출 시도 전에 규격×기기를 감지**하여 해당 시 "이 규격은 데스크탑에서 다운로드해주세요" 안내를 표시한다(MVP는 안내까지만, 타일 분할 렌더링은 이후 검토).

## 12. 데이터 모델

```typescript
interface Photo {
  id: string;
  src: string;            // 편집용 (장변 2000px 다운스케일)
  originalSrc: string;    // 추출용 원본 (IndexedDB Blob URL)

  // 모든 좌표·크기는 mm 단위
  x: number;
  y: number;
  width: number;
  height: number;

  rotation: number;       // deg
  scaleX: number;         // 좌우반전 = -1
  scaleY: number;         // 상하반전 = -1
  crop: { x: number; y: number; width: number; height: number };

  brightness: number;     // -1 ~ 1
  contrast: number;       // -1 ~ 1
  saturation: number;     // -1 ~ 1

  zIndex: number;         // 자유 배치 시 겹침 순서
  cellId?: string;        // 소속 레이아웃 슬롯 (grid 모드)
}

interface LayoutCell {
  id: string;
  x: number; y: number;       // mm
  width: number; height: number; // mm
}

type LayoutMode = 'grid' | 'free';
type Orientation = 'portrait' | 'landscape';
```

## 13. 상태 관리 (Zustand)

```typescript
// stores/paperStore.ts — 용지·인쇄 영역
interface PaperStore {
  paperId: string;                 // 'A4' | 'B4' | ... | 'custom'
  widthMm: number;                 // 방향 적용 후 실측
  heightMm: number;
  orientation: Orientation;
  bleedMm: 3 | 5;                  // 기본 3
  readonly safeAreaMm: 5;          // 고정
  setPaper(id: string, custom?: { w: number; h: number }): void;
  toggleOrientation(): void;
  setBleed(mm: 3 | 5): void;
}

// stores/layoutStore.ts — v2 신규 분리
interface LayoutStore {
  layoutMode: LayoutMode;
  layoutType: 1 | 2 | 3 | 4 | 6 | 9 | null;
  gutterMm: 0 | 2 | 5;             // 기본 2
  cells: LayoutCell[];             // 용지·방향·gutter에서 파생 계산
  setLayout(type: number): void;
  setGutter(mm: 0 | 2 | 5): void;
  setMode(mode: LayoutMode): void;
}

// stores/imageStore.ts — 사진 (zundo 적용 대상)
interface ImageStore {
  photos: Photo[];
  library: LibraryItem[];          // 업로드됐지만 미배치된 사진 목록
  selectedId: string | null;
  addPhotos(files: File[]): Promise<void>;   // HEIC 변환·EXIF 보정·다운스케일 포함
  assignToCell(photoId: string, cellId: string): void; // cover 채움 + 중앙 정렬
  updatePhoto(id: string, patch: Partial<Photo>): void;
  removePhoto(id: string): void;
  select(id: string | null): void;
}

// stores/frameStore.ts — 액자 (미리보기 전용, 2차)
interface FrameStore {
  frame: 'none' | 'black' | 'white' | 'wood' | 'gold' | 'silver';
  matWidthMm: 0 | 30 | 50;
  matColor: 'white' | 'ivory';
}

// stores/exportStore.ts — 추출
interface ExportStore {
  format: 'png' | 'jpg' | 'pdf';
  isExporting: boolean;
  exportError: string | null;
  canExportOnDevice(paper: PaperStore): boolean; // 모바일 대용량 감지
  runExport(): Promise<void>;
}
```

- **zundo(Undo/Redo)는 imageStore + layoutStore + paperStore에 적용**, frameStore/exportStore는 제외
- IndexedDB 자동 저장은 위 스토어 상태 + 이미지 Blob을 2초 디바운스로 직렬화

## 15. 릴리스 범위 (확정)

### 1차 (MVP)

- 용지 선택(방향 토글 포함) + Custom(A2 상한)
- 고정 레이아웃 1/2/4/6장 (방향 자동 변형)
- 업로드: JPG/PNG/WEBP/HEIC, EXIF 보정, 원본/편집용 이중 관리
- 슬롯 내 크롭·이동·확대·회전·좌우/상하 반전
- bleed(3/5mm)·재단선·안전선 표시
- PNG/JPG/300dpi PDF 추출 (모바일 대용량 감지 포함)
- Undo/Redo
- IndexedDB 자동 저장·복구
- 반응형 (데스크탑 3패널 / 모바일 바텀시트)

### 2차

- 자유 배치 (+스냅/정렬 가이드)
- 3장/9장 레이아웃
- 밝기/대비/채도 필터
- 액자 + 매트지 미리보기

### 3차

- AI 얼굴 인식 자동 배치 (face-api.js 또는 MediaPipe, 클라이언트 추론)
- 사용자 지정 레이아웃 편집기
- (장기) 서버사이드 CMYK 변환, 크로스 디바이스 이어하기

### 범위 결정 근거

- 액자 미리보기를 2차로 미룬 이유: 출력 파일에 영향 없는 순수 프리뷰라 핵심 가치(정확한 인쇄 파일)와 분리 가능.
- Undo/Redo·자동 저장을 1차에 넣은 이유: 실수 복구 불가·작업 유실은 이탈에 직결.
- AI를 3차로 미룬 이유: 모델 로딩(수 MB)·추론 시간이 첫인상 성능을 해치며, 수동 크롭 UX가 충분히 빠르면 필수가 아님.

## 16. 개발 요구사항

1. 모든 상태 좌표는 mm 단위로 저장한다 (§3). 화면 px 저장 금지.
2. 실제 인쇄 비율을 화면·추출 모두에서 정확히 유지한다.
3. React-Konva 기반 부드러운 Drag & Drop. 필터는 조작 종료 후 적용 정책 준수 (§8).
4. 300dpi 추출은 원본 이미지 교체 렌더링으로 수행한다 (§10).
5. 모바일·데스크탑 반응형 지원, 모바일 전용 조작 UI 포함 (§11).
6. TypeScript Strict Mode.
7. Tailwind CSS + Shadcn UI.
8. 리렌더 비용이 큰 캔버스 노드는 memoization 적용.
9. PDF는 bleed 포함 실측 mm 사이즈로 생성한다.
10. 컴포넌트 단위 분리로 유지보수성 확보.
11. 사진의 서버 전송 금지. 프라이버시 문구를 랜딩·에디터에 노출한다.
12. HEIC 변환·EXIF 보정·다운스케일은 업로드 파이프라인(`imagePipeline.ts`)에서 일괄 처리한다.

## 17. 사용자 흐름 (최종)

```text
용지 선택 (+ 방향)
  ↓
레이아웃 선택 (방향에 맞는 변형 자동 적용)
  ↓
사진 업로드 (HEIC 자동 변환 · EXIF 보정)
  ↓
슬롯으로 Drag & Drop → cover 자동 채움
  ↓
슬롯 내 이동·확대·회전·반전으로 미세 조정
  (실수하면 Undo · 이탈해도 자동 저장 복구)
  ↓
bleed·안전선으로 실제 출력 영역 확인
  ↓
(2차) 액자·매트지 미리보기
  ↓
300dpi PDF 생성 · 다운로드
  ↓
인쇄소에 바로 전달
```

### 핵심 보증

- 화면 = 출력물 (mm 진실의 원천으로 WYSIWYG 보증)
- 디자인 지식 없이 3분 이내 완성
- 사진은 기기를 벗어나지 않음
- 인쇄소 전달 가능한 300dpi·bleed 포함 파일
