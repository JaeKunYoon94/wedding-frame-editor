# 웨딩 액자 에디터 (Wedding Frame Editor)

결혼식 사진을 골라 액자 인쇄용 **300dpi 파일(PDF/PNG/JPG)** 로 바로 내보내는 브라우저 편집기입니다.
Next.js 14 · React Konva · Zustand로 만들었고, 용지(A2~A5)·레이아웃(1·4·9·16장)·여백·재단 여백(bleed)을 정하면
**화면에 보이는 그대로 용지 실측 크기의 인쇄 파일**이 나옵니다. 서버가 없어 사진은 내 기기 밖으로 나가지 않습니다.

**▶ 바로 써 보기: https://wedding-frame-editor.vercel.app/** — 설치 없이 브라우저에서 열고, 사진이 없으면 상단 **샘플** 버튼으로 체험할 수 있습니다.

![에디터 화면 — 4장 레이아웃에 사진을 배치하고 선택한 모습](docs/images/03-selected.png)

## 왜 만들었나

**아내가 결혼식 사진을 액자로 뽑고 싶다고 부탁한 데서 시작했습니다.**
사진 몇 장을 A4·A3 액자에 맞춰 배치하려 했더니, 일반 사진 편집 앱은 mm 단위 여백이나 300dpi 출력을 맞추기 번거롭고
인쇄소용 툴은 너무 무거웠습니다. 그래서 "사진 올리기 → 칸에 끌어 놓기 → 다운로드" 세 단계로 끝나는 전용 편집기를 직접 만들었습니다.

개발 측면에서는 AI 코딩 도구(Claude Code)를 단순한 코드 생성기가 아니라 **규칙·검증 절차를 갖춘 협업자**로 쓰는 과정을 보여 주는 것도 목표였습니다.
([AI 활용 방식](#ai-활용-방식) 참고)

## 주요 기능

| 기능 | 구현 방식 |
| --- | --- |
| **mm 기준 WYSIWYG 조판** | 모든 좌표를 mm로 저장하고 화면은 `mm × screenScale`, 출력은 `mm / 25.4 × 300`으로 변환 (`src/lib/convertMM.ts`). 화면과 출력이 같은 원천에서 계산돼 어긋나지 않습니다. |
| **레이아웃·여백 계산** | 용지·장수·간격·여백(네 변 동일 / 변마다 따로)을 입력받아 슬롯 사각형을 산출 (`src/lib/layoutCalc.ts`). 한 변 여백에 상한을 두어 사진 영역이 무너지지 않게 했습니다. |
| **슬롯 고정 + 내부 크롭** | 사진을 슬롯에 놓으면 cover로 자동 채움. 슬롯에 clip된 상태로 드래그·확대·회전·반전하며, 빈틈이 생기는 방향으로는 이동을 막습니다. |
| **업로드 파이프라인** | HEIC → JPEG 변환, EXIF 방향 보정 후 원본은 IndexedDB에, 편집용은 장변 2000px 축소본으로 이중 관리 (`src/lib/imagePipeline.ts`). 편집은 가볍게, 출력은 원본으로. |
| **인쇄 파일 추출** | 내보낼 때 캔버스를 `mode='export'`로 다시 그려 가이드(bleed·재단선)를 빼고, 축소본을 원본으로 교체해 렌더링 후 재단 영역만 crop. 기기 캔버스 한계(모바일 4096px / 데스크탑 8192px)를 넘으면 비율을 유지해 자동 축소 (`src/lib/exportPdf.ts`). |
| **Undo/Redo** | Zustand + zundo로 편집 상태 50단계 기록. |
| **모바일 대응** | 바텀시트 UI, 탭-투-배치(사진 탭 → 슬롯 탭), 두 손가락 핀치 줌. |
| **샘플 모드** | 사진이 없어도 샘플 9장으로 바로 체험. 편집 모드로 돌아가면 샘플만 걷히고 내 사진은 남습니다. |
| **흑백 필터** | 선택한 사진 단위로 적용, 출력물에도 반영. |

## 실행 방법

배포본은 https://wedding-frame-editor.vercel.app/ 에서 바로 쓸 수 있습니다(Vercel). 로컬에서 실행하려면 Node.js 18.17 이상이 필요합니다.

```bash
npm install
npm run dev        # http://localhost:3000
```

```bash
npm run typecheck  # tsc --noEmit
npm run build && npm start
```

## 사용법

### 1. 시작하기

랜딩 화면에서 **지금 만들기**를 누르면 에디터가 열립니다. 사진이 없으면 상단 **샘플** 버튼으로 바로 체험할 수 있습니다.

![랜딩 화면](docs/images/01-landing.png)

### 2. 사진 배치

- 왼쪽 패널에 사진(JPG/PNG/WEBP/HEIC)을 끌어다 놓거나 눌러서 고릅니다.
- 사진을 캔버스 슬롯으로 드래그하면 슬롯을 꽉 채우도록 맞춰집니다. 모바일은 사진을 누른 뒤 슬롯을 누릅니다.

### 3. 사진 다듬기

캔버스에서 사진을 누르면 선택되고, 오른쪽 아래에 **사진 도구 상자**가 나타납니다(데스크탑).
사진을 직접 드래그해 보이는 부분을 옮길 수도 있고, 설정 패널에서 90° 회전·흑백 필터를 적용합니다.

### 4. 용지·레이아웃·여백

![여백 '변마다 따로' 설정](docs/images/04-margins.png)

- **용지** A2~A5, 세로/가로 · **레이아웃** 1·4·9·16장(1장은 꽉 채움/정사각형), 사진 간격
- **여백** 네 변 동일(슬라이더·프리셋) 또는 변마다 따로(mm 입력, Enter나 포커스 이탈 시 반영)
- **Bleed** 0/3/5mm — 화면의 회색 영역은 재단 가이드일 뿐 출력 파일에는 찍히지 않습니다.

### 5. 다운로드

설정 패널 맨 아래에서 **PDF / PNG / JPG**로 내려받습니다. 출력 크기는 용지 실측 그대로입니다(A4 → 210×297mm, 2480×3508px).

### 조작법

| 입력 | 동작 |
| --- | --- |
| 사진 드래그 → 슬롯 | 배치 (cover 자동 채움) |
| 슬롯 안 사진 드래그 | 보이는 부분 이동 |
| 도구 상자 ↑ ↓ ← → / ＋ － | 2mm씩 이동 / 확대·축소 |
| 도구 상자 좌우·상하 반전 | 사진 뒤집기 |
| `Delete` / `Backspace` | 선택한 사진 슬롯에서 제거 |
| `Esc` | 선택 해제 |
| `Ctrl`(⌘) + `Z` / `Ctrl`(⌘) + `Shift` + `Z` | 실행 취소 / 다시 실행 |
| 모바일: 사진 탭 → 슬롯 탭, 두 손가락 핀치 | 배치 / 확대·축소 |

## 기술 스택과 구조

**Next.js 14 (App Router) · TypeScript · React Konva · Zustand + zundo · Tailwind CSS · framer-motion · idb · jsPDF · heic2any · exifr**

```
src/
├─ app/            # 랜딩(/), 에디터(/editor)
├─ components/
│  ├─ Editor.tsx   # 3패널(데스크탑)/바텀시트(모바일) 통합, 캔버스는 단일 마운트
│  ├─ canvas/      # PaperCanvas(인쇄 가이드·슬롯·사진 노드), PhotoToolbar
│  └─ panels/      # LibraryPanel, SettingsPanel
├─ stores/         # editorStore (zundo로 Undo/Redo)
├─ lib/            # convertMM, layoutCalc, paperSizes, imagePipeline, exportPdf, storage, samples
└─ types/
```

설계 원칙

- **mm가 진실의 원천** — 화면 픽셀이나 출력 픽셀을 상태로 저장하지 않습니다. 배율이 바뀌어도 레이아웃이 그대로입니다.
- **완전 클라이언트 사이드** — 서버·외부 전송이 없습니다. 원본 사진은 IndexedDB에만 두고 에디터 진입 시 정리합니다.
- **화면과 출력은 같은 컴포넌트** — `PaperCanvas` 하나를 `mode`만 바꿔 화면/출력에 같이 써서 WYSIWYG를 보장합니다.

디자인은 `DESIGN.md` 기준의 "사진이 주인공인 갤러리 톤"입니다. 파치먼트 배경 + 흰 패널, 포인트색은 한 가지만 쓰고, 토큰은 `tailwind.config.ts`, 폰트는 `next/font`로 자체 호스팅합니다.

## AI 활용 방식

Claude Code로 개발했습니다. 코드를 받아 붙이는 대신, **AI가 지켜야 할 규칙과 결과를 검증하는 절차를 먼저 만들고** 그 안에서 작업하게 했습니다.

| 장치 | 역할 |
| --- | --- |
| `CLAUDE.md` | 시큐어 코딩(업로드 검증, XSS 금지 API, `blob:` URL 해제, 사진 외부 전송 금지)·한글 주석·디자인 규칙을 명시해 모든 작업에 적용 |
| `.claude/agents/qa-tester` | 기능 변경 후 Playwright로 데스크탑·모바일에서 클릭·드래그·탭과 콘솔 에러를 검증해 표로 보고 |
| `.claude/agents/qa-fixer` | qa-tester의 실패 항목만 받아 최소 diff로 수정 |
| `.claude/agents/security-reviewer` | "서버 없음" 위협 모델 기준으로 XSS·역직렬화·업로드·사진 유출 경로·의존성 점검 (보고만, 수정 안 함) |
| `.claude/agents/readme-updater` + `.githooks/pre-push` | push 직전 아직 올라가지 않은 커밋의 diff를 근거로 README를 코드와 맞춤 |

AI는 기능 초안 작성, 버그 원인 분석(예: 모바일 흑백 필터 미적용, 다운로드 시 흰 용지), 리팩터링, 테스트·보안 점검에 활용했습니다.
기능 범위와 우선순위(`docs/기획안_v2.md`), mm 기준 좌표계 같은 구조 결정, 실제 출력물 확인, 최종 코드 리뷰는 직접 했습니다.

README 자동 갱신 훅은 최초 1회 아래 설정이 필요합니다. 건너뛰려면 `SKIP_README_AGENT=1 git push`.

```bash
git config core.hooksPath .githooks
```

## 알려진 한계와 다음 계획

- **색 공간**: 브라우저 캔버스 한계로 출력은 sRGB입니다. 인쇄소 CMYK 변환은 장기 과제입니다.
- **대형 용지 on 모바일**: A2처럼 기기 캔버스 한계를 넘는 규격은 비율을 유지한 채 해상도를 낮춰 추출합니다.
- **작업 저장 없음**: 새로고침하면 편집 상태가 초기화됩니다(원본 사진은 에디터에 들어올 때 IndexedDB에서 정리합니다).
- **구현했지만 숨긴 기능**: 폴라로이드/인생네컷 테두리, 액자·벽면 목업 미리보기, 자유 배치 텍스트 — 완성도를 다듬은 뒤 기능 플래그(`*_ENABLED`)를 켤 예정입니다.
- **다음 릴리스**: 밝기/대비/채도 필터 → AI 얼굴 인식 자동 배치, 커스텀 레이아웃 편집기.
